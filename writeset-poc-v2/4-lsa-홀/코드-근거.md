# 슬레이브 LSA 홀 분석 — 코드 근거

[[lsa-hole-분석]]의 서술을 뒷받침하는 `log_applier.c` 위치 모음이다(브랜치 `feature/parallel_applylogdb_writeset_rw_slot`, 13068 라인). 별도 표기가 없으면 파일은 `src/transaction/log_applier.c`다. 라인 번호는 작성 시점 기준이라 함수명과 함께 본다.

## 네 LSA와 게이트 상태

| 대상 | 위치 | 메모 |
| --- | --- | --- |
| `final_lsa` (리더 읽기 위치) | `:12707` | 워커보다 앞서 달림 |
| `committed_lsa` (프론티어) | `:2536`, `:2586-2612` | gap-free 프론티어로만 단조 전진, HWM 아님 |
| `committed_rep_lsa` (모니터링) | `:9442-9448` | 정확성 게이트에서 제외 |
| `required_lsa` (purge LWM) | `:4663-4693` | 살아있는 슬롯(tranid>0) 최소 start |
| 게이트 프론티어 `la_Gate_frontier` | `:1501` | gap-free 완료 프론티어 |
| 커밋순서 FIFO `la_Gate_order_*` | `:1606-1631` | head 완료 시 프론티어 전진 |
| 완료집합 `la_Gate_completed_slots` | `:1484`, 용량 `:1474-1475` | 홀 목록, 오픈해싱, in-memory 전용 |
| park 큐 `la_Gate_pending_*` | `:1487-1488` | 의존 미충족 대기 |

## 증가 (프론티어 전진)

- `committed_lsa` 단조 전진: `:2536`, `:2586-2612`.
- 완료 등록 `la_gate_mark_completed(commit_lsa)`: `:2522-2531`(성공 LOG_COMMIT만 `:2524`).
- 리더 FIFO push: `:10133`. head 연속 전진: `:1607-1631`.
- `required_lsa` 유지: 슬롯 해제는 retire에서만 `:2579-2584`, park 슬롯 리더가 선점 `:10110`.
- 완료집합 용량 `LA_GATE_SET_CAPACITY = 1<<18`: `:1474-1475`. 가득 시 프론티어 이하 prune 후 실패 `ER_HA_GENERIC_ERROR`: `:1646-1654`.
- `required_lsa` 재계산은 `la_log_commit` 안에서만 `:10443`, retire persist는 재계산 없이 기록 `:5342-5344`(retire persist `:2660`).

## 재시작 / persist

- 진행 정보 원자적 UPDATE: `la_update_ha_last_applied_info` `:3646-3654`, 한 행 한 트랜잭션 `:5305-5344`, retire 저장 `:2655-2668`.
- 재시작 로드: `:5172-5180`.
- `committed_lsa := required_lsa`: `:12182`. `final_lsa := committed_lsa`(`la_apply_pre`) `:5933-5937`, 호출 `:12224`.
- 게이트 완전 리셋 `la_gate_init`: `:1842-1867`. 첫 커밋 재시드: `:10128-10132`.
- skip 게이트 — 리더 `LSA_GT(final, committed_lsa)`: `:10062-10064`. 워커 `LSA_LE(commit_lsa, last_committed_lsa)`: `:9414-9426`.
- PK 멱등 근거 주석(R3): `:9442-9448`. 지원 대상 판정 `la_is_supported_poc_item`: `:9449`.

## 재적용이 조용하지 않은 경로 (서버 = `locator_sr.c`)

- INSERT 재적용 = 흡수 없이 삽입 시도 → unique 위반: `locator_sr.c:7026-7033`.
- 객체 단위 topop abort + 에러 수집 후 계속: `locator_sr.c:7083-7092`.
- DELETE 재적용 = 대상 없음 `ER_OBJ_OBJECT_NOT_FOUND`: `locator_sr.c:6856-6861`.
- 클라이언트 에러 로그 + `fail_counter++`: `log_applier.c:8160-8218`(핵심 `:8190-8194`). persist: `:5374`.
- 재접속 유발 목록(unique 위반·NOT_FOUND 없음): `log_applier.h:34-46`.
- 원 에러(서버 로그): `btree.c:28716, 28789`.

## 장애

- head 실패 즉시 반환: `:2569-2572`. 에러 수집→shutdown: `:12777-12787`, `:12250-12265`.
- 워커 재시도/무시: `:9514`. 서버다운 승격 `ER_NET_CANT_CONNECT_SERVER`: `:9509-9513`.
- 워커 스레드 모델: `:3623-3643`.
- 의존 라벨 누락 = 독립 디스패치: `:10116-10124`.

## failover

- 역할 변경 `is_role_changed`→`ER_INTERRUPTED`: `:10200-10210`, dbname 락 해제 `:12752-12757`.
- lsaguard 프론티어 clamp: `:12370-12386`.
- peer 재구축 감지 → `reinit_copylog`/apply_info 삭제: `:12791-12807`.

## B5 대조 — MySQL 9.7 idempotent

- `replica_exec_mode` STRICT/IDEMPOTENT 유효: `sys_vars.cc:3993-4005`.
- INSERT overwrite: `log_event.cc:12362`. 행 없음류 무시: `log_event.cc:565-597`, `:8700`.
