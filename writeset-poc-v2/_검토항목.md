# 재구성 검토 항목 (한 번에 훑기용)

재구성하며 판단이 모호했던 곳을 모았다. 각 문서 본문에도 `> [!question] 검토:` 콜아웃으로 같은 표시가 있다. 재구성이 끝난 뒤 한 번에 검토한다.

## 전역
- **파일명·폴더**: `숫자-한글` 폴더 + 하이픈 파일명으로 통일. 이대로 확정?
- **링크**: 지금은 Obsidian 위키링크. GitHub push 직전 표준 마크다운 링크로 일괄 변환 예정.
- **to-ai 코멘트**: GitHub 정리본에서는 전부 제외. 재구성 후 별도 리뷰.

## 2-mysql-테스트 (원본 2)
- **프레임 정정 보류**: 제목·요약·태그를 "대조 실험 보고서"에서 "실측 조사(사전 연구)"로 바꾸는 안이 있었으나, 일단 원본 그대로 두고 to-ai만 제거해 옮겼다. 재구성 후 리뷰 때 프레임을 정정할지 결정.

## 3-충돌제거/설계
- **한계 문서 — 후속 설계 아이디어**: 슬롯 분리는 참조 유래 의존을 프론티어 대기로 처리해, 부모 DELETE가 자식 앞 무관한 트랜잭션의 홀까지 기다린다. 무관 트랜잭션을 안 끌어들이려면 "부모 키별 참조 세대 다중 의존" 같은 더 정밀한 표현이 필요(확정안 아님). 이 후속 아이디어를 정리본에 어느 수준으로 남길지.
- **자료조사 좌표 참조**: 원본에 "자료조사 3-6-5" 같은 좌표 참조가 여럿 있었다. 재구성본은 대부분 서술로 바꿨으나, 남은 좌표 참조를 서술형으로 다듬는 패스 필요.

## 3-충돌제거/구현
- **near-verbatim 이관**: fk-브랜치-코드리뷰(1683줄)·테스트-방법(333줄)은 코드·방법 문서라 원본 그대로 옮겼다(to-ai 없음). 과도한 재작성 대신 코드 상세를 보존. 필요 시 도입부만 다듬는 폴리시 패스 가능.

## 4-lsa-홀 (원본 8)
- **코드 분리**: file:line 코드 상세를 `코드-근거.md`로 분리하고 본문은 개념만 남김(CLAUDE.md 규칙). 이 분리 방식 OK?
- **반대 방향 폐기 근거**: "완료 대신 홀을 기록"하는 반대 설계를 왜 안 쓰는지를 본문에 어느 수준으로 남길지.
- **미확인 3건**: ① failback 시 writeset 특화 재초기화 코드 못 찾음(현재 없음 추정), ② 완료집합 상한을 실제로 치는 워크로드 조건 정량 미검증, ③ B4 단기책을 정식 설계에 포함할지(완료 마킹으로 바로 가면 불필요).
