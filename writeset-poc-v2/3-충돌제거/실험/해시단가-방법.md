# 해시 단가 실험 — 측정 방법

writeset을 도입하면 마스터는 트랜잭션마다 변경한 키를 해시로 만들어 히스토리 맵에 넣고 조회한다. 이 실험은 그 해시 처리가 트랜잭션 실행 시간의 몇 %인지, 무시할 수준인지를 확정한다. 결과는 [[해시단가-결과]]에 있고, 부하가 커질 때 폭주하는지(경합)는 [[경합확장성-방법]]에서 따로 본다.

측정은 두 방향으로 한다. **실측**은 실제 HA 서버에서 커밋 경로에 계측을 심어 실환경 비용(캐시 미스, latch 대기 포함)을 재고, **유닛 벤치**는 서버 없이 함수만 돌려 무경합·웜캐시의 순수 CPU 하한을 잰다. 두 값이 같은 자릿수에서 만나면 실측 단가가 계측 오류가 아님이 교차 확인된다.

## 1. 계측 지점 — 트랜잭션 흐름을 따라 네 곳

writeset이 트랜잭션 한 건에 더하는 일은 시간 순서로 수집·조회·게시 세 단계다. 이 셋과, 그것을 담은 커밋 전체까지 네 곳을 잰다.

- **collect(수집)** — 문장 실행 중, 행마다 그 행의 키를 직렬화하고 해시해 트랜잭션의 목록에 담는다. 커밋이 아니라 INSERT/DELETE/UPDATE 실행 도중 행 단위로 일어나므로, 키를 추가하는 함수를 시간 래퍼로 감싸 트랜잭션별로 누적한다(행마다 로그를 남기면 로그 I/O가 측정을 오염시키므로 누적만 한다). 쓰기(WRITE) 키는 직렬화+해시, 참조(REF) 키는 여기에 부모 PK 도메인으로의 캐스팅이 더해진다.
- **probe(조회)** — 커밋 직전, 모은 키로 전역 히스토리 맵을 조회해 이 트랜잭션의 의존을 계산한다. 이 조회는 전역 latch 안에서 일어나므로, 시각을 latch 획득 전에 찍어 "latch 대기 + 조회"를 함께 잰다(대기도 실제 비용이다).
- **flush(게시)** — 커밋이 확정되면 이 트랜잭션의 키를 히스토리 맵에 써넣는다. probe와 마찬가지로 latch 안이라 획득 전부터 잰다.
- **commit_total(커밋 경로 전체)** — 로컬 커밋 함수의 진입부터 리턴까지 전부. probe·flush가 커밋 경로에서 차지하는 비중의 분모가 된다. 이 함수는 writeset 없는 develop에도 있어, 유무 비교의 기준이 된다.

## 2. 시간의 포함 관계와 비율

네 측정값과 벤치 셸이 밖에서 재는 세션 시간의 포함 관계는 다음과 같다.

```
세션 실행 시간  (벤치 셸: csql 기동 ~ 종료)
 ├─ 문장 실행 구간 ── collect가 행마다 흩어져 있음
 ├─ commit_total ─── 커밋 경로 전체
 │    ├─ probe
 │    └─ flush
 └─ 클라이언트 왕복·파싱·접속
```

비율은 두 가지만 쓴다. 모든 결과가 같은 형식으로 병기한다.

- **(a) 실행 대비** = (collect+probe+flush) ÷ 그 커밋이 소비한 실행 시간. "사용자가 체감하는 실행 전체에서 writeset이 차지하는 몫"이다.
- **(b) 커밋 경로 대비** = (probe+flush) ÷ commit_total. "커밋 순간만 떼어 보면 얼마나 몰리는가"다. collect는 커밋 밖(문장 실행 중)에서 일어나므로 (b)에 넣지 않고 절대치(키당 ns)로 따로 말한다.

측정 자체의 오차 하나: collect는 키마다 시각 함수를 두 번 호출하는데, 그 호출 비용(약 40ns)이 섞이므로 순수 해시 단가는 표기값보다 조금 낮다.

## 3. 유닛 벤치 — 순수 CPU 하한

실측 단가가 계측 오염으로 부풀려진 값이 아닌지 교차 확인하려고, 서버 없이 함수만 도는 유닛 벤치를 함께 쓴다. Catch2 기반이며, WRITE·REF add(수집), probe(맵 조회), flush(맵 게시) 각 함수를 웜캐시·단일 스레드·무경합에서 키당 시간으로 잰다. 이 값은 실환경 비용(캐시 미스, latch 경합)이 얹히기 전의 하한이라, 실측보다 작게 나오는 게 정상이다. "develop 수행시간 + 유닛 값"으로 writeset 빌드의 수행시간을 하한 예측하는 용도로도 쓴다.

## 4. 환경과 워크로드

- 마스터·슬레이브 HA 2노드, release 빌드. 브랜치는 세 구성(PK만 / FK 단일 슬롯 / FK read-write 슬롯)에 develop 기준선을 더한 넷. 측정 실행 시점의 HEAD 해시를 로그와 결과에 기록한다.
- **대량 워크로드**: 부모·자식 각각 10만 행을 1커밋으로 INSERT. 한 커밋에 키가 5만~10만 개 쌓여 해시 비용이 ms 단위로 커져 측정 오차 위로 드러난다.
- **단건 워크로드**: 한 행짜리 INSERT를 autocommit으로 1만 번 반복(커밋 1만 개 표본). 커밋당 키가 1~2개뿐이라, 대량 커밋에서 5만 행에 가려 안 보이던 커밋당 고정비가 드러난다.
- 측정 조건을 구성 간 통일해(모두 10만 행 1커밋, 또는 1행 1커밋 × 1만) 세로 방향 직접 비교가 성립하게 한다. 원자료 위치는 [[해시-벤치-원자료]]에 있다.

> [!note] 계측 코드
> collect/probe/flush/commit_total 네 지점의 실제 계측 코드(시간 래퍼 위치, 출력 방식)는 원본 6의 부록 A에 있었다. 코드 상세가 필요하면 그쪽을 참조한다. 이 정리본에서는 방법 개념만 둔다.
