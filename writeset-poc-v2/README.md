# writeset v2 — applylogdb 병렬 적용 문서

CUBRID의 복제 적용기(applylogdb)를 병렬화하는 writeset v2 작업의 설계·실측 문서 모음이다. 마스터가 트랜잭션마다 변경한 키의 해시를 넘겨주면, 슬레이브가 그 해시로 트랜잭션 사이의 의존 관계를 판정해 서로 독립인 트랜잭션을 병렬로 적용한다.

작업은 두 방향으로 나뉜다. 먼저 **트랜잭션 충돌 제거**(같은 데이터를 건드리는 트랜잭션만 직렬화하고 나머지는 병렬), 그다음 병렬 적용이 만드는 **LSA 공백(hole) 처리**(적용 순서를 보장하지 않고 넘어온 구간을 재시작·장애 시에도 안전하게 다루기)다.

## 읽는 순서와 문서 지도

| 순서 | 폴더 / 문서 | 역할 |
| --- | --- | --- |
| 1 | `1-mysql-사전조사/자료조사` | MySQL 9.x의 writeset·FK 처리 방식을 문헌과 소스로 조사. v2 설계의 출발점 |
| 2 | `2-mysql-테스트/fk-병렬화-실측` | MySQL 9.7에서 FK 자식 트랜잭션의 병렬 복제를 실측. 형제 과직렬화(#110071) 확인 |
| 3 | `3-충돌제거/` | v2 방향 1 — 충돌 제거 설계·구현·실험 (아래 세분) |
| 4 | `4-lsa-홀/` | v2 방향 2 — 병렬 적용이 만드는 LSA 공백의 분석과 처리 |

### 3-충돌제거 (방향 1)

| 칸 | 내용 |
| --- | --- |
| `설계/` | 설계 확정본, 순서 역전 한계, 제약조건 커버리지 |
| `구현/` | 소스 근거, FK 브랜치 코드 리뷰, 테스트 방법 |
| `실험/` (병렬화) | 슬레이브에서 형제 트랜잭션이 실제로 병렬 적용되는가 — `병렬화-방법` / `병렬화-결과와원인` |
| `실험/` (해시 단가) | WRITE·REF 해시가 실행 시간의 몇 %인가 — `해시단가-방법` / `해시단가-결과` |
| `실험/` (경합·확장성) | 동시 커밋·키 수가 커질 때 전역 해시 맵 lock이 폭주하지 않는가 — `경합확장성-방법` / `경합확장성-결과` |
| `실험/` (부속) | `sbr-측정방식`(측정 함정), `해시-벤치-원자료`(원자료 위치) |
