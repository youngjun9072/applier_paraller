## 문제 15

**[심각도: 사소] `ALTER TABLE ... REPLICATION=ON|OFF` 절이 parse tree 재출력(`pt_print_alter_one_clause`)에서 case 누락으로 조용히 사라진다 — 파스트리를 다시 SQL로 찍는 모든 경로에서 이 절이 소실된다**

**위치** `src/parser/parse_tree_cl.c:5775-5860` (`pt_print_alter_one_clause`의 `switch (p->info.alter.code)`에 `PT_CHANGE_REPLICATION` case 없음). 대비: 형제 절 `PT_CHANGE_TABLE_COMMENT`(`:5793`, `" comment = "`), `PT_CHANGE_COLLATION`(`:5799`)은 print case를 갖고 있다. 디스패치·CREATE 경로는 정상: `do_alter` switch(`execute_schema.c:2033`)와 CREATE용 `pt_print_table_option`(`parse_tree_cl.c:8041`, `"replication = "`)에는 각각 처리가 있다.

**로직 설명 (콜체인)**
파서는 `ALTER TABLE t REPLICATION=OFF`를 `class_replication_spec` 규칙(`csql_grammar.y:19887`)으로 받아
alter 노드의 `code = PT_CHANGE_REPLICATION`, `alter_clause.replication.tbl_replication = <PT_VALUE 0/1>`로 세운다
(`csql_grammar.y:5862-5871`). 실행 경로 `do_alter()`는 이 code를 보고 `do_alter_change_replication()`을 정확히 호출하므로
**기능 동작 자체는 정상**이다.

문제는 파스트리를 **다시 문자열로 역출력(unparse)**하는 `parser_print_tree` → `pt_print_alter_one_clause` 경로다.
이 switch에는 `PT_CHANGE_REPLICATION` case가 없어 `default: break;`로 떨어지고, 그 결과 재출력된 문자열에는
` REPLICATION=OFF` 절이 통째로 빠진다. CREATE의 테이블 옵션 출력(`pt_print_table_option`)에는 REPLICATION case가
추가돼 있는데, **ALTER 전용 절 출력에만 대칭적으로 누락**된 것이다(COMMENT/COLLATION은 양쪽 다 있다).

**문제 시나리오**
마이그레이션·스키마 스냅샷 도구를 쓰는 애플리케이션 개발자 관점에서, 파스트리 재출력이 실제로 소비되는 지점에서
"실행한 DDL"과 "재구성된 DDL"이 어긋난다. 예:
- 서버가 에러 컨텍스트나 진단 목적으로 문장을 재구성해 로그에 남길 때, `ALTER TABLE t REPLICATION=OFF`가
  `ALTER TABLE t`로 찍혀 원인 추적이 왜곡된다.
- 파스트리를 재출력해 정규화·재파싱하는 내부 도구/테스트가 있다면, 재출력 결과를 다시 실행해도 REPLICATION 변경이
  적용되지 않는다(원문과 의미가 달라짐).

**영향 범위에 대한 정직한 한정**
DDL의 문 기반 복제(SBR)는 파스트리 재출력이 아니라 **원본 사용자 텍스트**를 그대로 실어 나른다
(`do_replicate_statement`가 `statement->sql_user_text`를 사용, `execute_statement.c:16519,16722`에서 확인).
따라서 이 누락이 **마스터→슬레이브 DDL 복제 자체를 깨뜨리지는 않는다**. 실사용 영향이 제한적이라 심각도를 "사소"로
둔다. 다만 형제 절과의 명백한 대칭 위반이자, "파스트리에서 SQL을 재구성한다"는 불변식을 조용히 깨는 코드 결함이므로
기록한다.

**제안** `pt_print_alter_one_clause`의 switch에 아래를 추가해 형제 절과 대칭을 맞춰라(값 0/1 → OFF/ON 매핑 필요):
```c
case PT_CHANGE_REPLICATION:
  q = pt_append_nulstring (parser, q, " replication = ");
  q = pt_append_varchar (parser, q,
        pt_print_bytes (parser, p->info.alter.alter_clause.replication.tbl_replication));
  break;
```
(신규 코드 — 이 기능 diff가 만든 결함. 기존 67건·유지 12건과 뿌리(loc·원인)가 겹치지 않음: K-list에 `parse_tree_cl.c` 항목 없음)
