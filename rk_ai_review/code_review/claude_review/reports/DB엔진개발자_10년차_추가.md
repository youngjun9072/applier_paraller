> 전 페르소나 병합 이슈 67건(dedup_existing.json: K-1~K-69 + K2-1~K2-3)을 기준선으로 두고,

## 이번 라운드에서 새로 훑은 영역과 판단 근거

3차에서는 "2차 리포트(17건)와 병합 67건이 아직 손대지 않은 파일·함수"를 우선 타깃으로 삼아,
diff 추가/변경 코드를 Read로 읽고 콜체인을 정의 점프/참조로 따라가며 검증했다. 아래는 영역별로
"무엇을 봤고 왜 신규가 아닌가"를 남긴다.

### A. 파서·파스트리 골격 (parse_tree.h, parse_tree_cl.c, csql_grammar.y, csql_lexer.l, semantic_check.c)
- `PT_CHANGE_REPLICATION`/`PT_TABLE_OPTION_REPLICATION` enum 추가, `pt_alter_info.replication` 유니온
  멤버 추가, `pt_print_table_option`의 `"replication = "` 출력, `class_replication_spec`/
  `opt_replication_option` 규칙, 렉서 토큰, `pt_check_create_entity`의 CREATE 중복 절 검사(정상)까지 확인.
- REPLICATION 예약어화 회귀는 **문제 8 / K-11**, ALTER 중복 절 무성 무시는 **문제 17 / K-20**로 이미
  보유·병합됨. `opt_replication_option`의 빈 값 기본 ON(=1)은 CREATE/ALTER 공통 관례(ENCRYPT/COMMENT와
  동일)라 결함 아님. `pt_print_table_option`의 `=` 표기는 파스트리 재출력(트레이스)용으로, SHOW CREATE
  표기 불일치(**K-50**)와 같은 뿌리라 별건 아님.

### B. 카탈로그·error_code·유틸 등록 (error_code.h, dbi_compat.h, schema_system_catalog_install*.cpp, utility.h, util_admin.c)
- 신규 에러코드 4종(-1375~-1378) 정의·`ER_LAST_ERROR` 갱신·en/ko 메시지 확인. 4종 모두 실제 사용처
  존재(-1375/-1377=execute_schema.c, -1376=do_alter_change_replication, -1378=util_cs.c rkcheck).
- `dbi_compat.h`에 신규 코드 미반영이나, **-1374(ER_PARTITION_TABLE_NAME_OVERFLOW) 등 기존 -137x 대역이
  애초 dbi_compat.h에 존재하지 않음**을 확인 — 이 대역은 클라이언트 헤더 미러 대상이 아니므로 결함 아님.
- 1375 국문 메시지의 "테이블 생성 시" 고정 표기는 ALTER 경로에서도 재사용되어 부정확하나 이는 **K-23**.
- `db_class` 뷰 `is_replication_class` 중간 삽입은 **문제 13 / K-19**, UTIL_INDEX enum 중간 삽입은
  **문제 18 / K-61**, rkcheck 옵션맵(util_admin.c) 신규 등록은 정상 관례.

### C. 스키마 매니저·클래스 오브젝트 (schema_manager.c, class_object.c/.h, schema_template.c)
- `sm_is_replication_class`의 NULL/fetch 실패 assert+false 삼킴은 **K-7**, 그 패턴 반복 이식은 **K-8**.
- `classobj_copy_pk_and_uk_notnull_constraints`가 범용 `classobj_init_attribute`에 얹혀 부작용을 낳는

  판정이 서버측 "전부 NOT NULL"과 어긋나는 핵심 불일치는 **문제 1 / K-5**.
- `find_index_catalog_class` 데드코드는 **문제 11 / K-33**로 보유.

### D. 서버측 복제 판정·인덱스 (object_representation_sr.c, heap_file.c, btree.c, locator_sr.c)
- `or_class_is_replication_on`의 매직넘버 32는 **문제 10 / K-10**. `or_is_replication_candidate_key`가
  filter/function 인덱스를 구분하지 않는 건 **K-26**, 인덱스 배열 순서 의존 마스터/슬레이브 독립 재계산은
  **K-58**, PK/UK 재할당 무경고는 **K-56**.
- `heap_get_class_repl_on`(#7697 흡수분, int 반환+out-param)은 **정상 버그픽스**로 재확인. INSERT/DELETE
  경로(`locator_add_or_remove_index_internal`)의 인덱스 루프 내 반복 호출은 **K2-2/K-12**.
- `locator_update_index`의 옛 `heap_is_replication_class` 잔존 호출은 **작업지시서 §7 가정대로 수정 완료
  간주(지적 금지)**.
- **[검증 후 제외]** `btree_get_rkey_btid`(btree.c:8263)가 RK 후보 미발견 시 `NO_ERROR` + NULL btid를
  돌려주고, 슬레이브측 유일 호출자 `locator_repl_prepare_force`(locator_sr.c:6848)가 `BTID_IS_NULL`을
  검사하지 않고 그대로 `xbtree_find_unique`에 넘겨 `ER_OBJ_OBJECT_NOT_FOUND`로 오도한다. 그러나
  base(b646647ec)의 `btree_get_pkey_btid` + 동일 호출부도 NULL 미검사였음을 `git show`로 확인 —
  **feature가 만든 결함이 아닌 기존 성질**(§5 "기존")이며, RK 확장으로 도달성이 커지는 부분은 이미
  **문제 1 / K-5(무성 유실)·K-58(순서 불일치)** 로 다뤄짐. 신규로 세지 않음.

### E. DDL/DML 경로 (execute_schema.c, execute_statement.c)
- `IS_REPL_CONSTRAINT_RELATED_ALTER`가 첫 절 코드만 보는 게이트 버그는 **문제 3 / K-1**, MODIFY/DROP
  INDEX/RENAME 누락은 **문제 4 / K-6**. `do_alter`의 `db_find_class` NULL 미검사→`sm_is_replication_class`
  전달은 **문제 15 / K-17**. `do_alter_change_replication`의 코멘트용 세이브포인트 재사용은 **문제 16 /
  K-9**, FK/역참조 미재검증은 **K-54**.
- **[검증 후 제외]** `do_create_entity`의 REPLICATION=OFF 분기가 오류 시 `goto error_exit`가 아닌 `break`를
  쓴다(execute_schema.c:10280). 그러나 이 `break`는 encrypt(10307)/collation(10314) 등 같은
  `case PT_CLASS:` 내 형제 분기와 동일 패턴이고, 스위치 직후 `if (error != NO_ERROR) goto error_exit;`
  (10357)로 수렴하므로 동작상 등가 — 스타일 비일관일 뿐 결함 아님.
- `truncate_need_repl_log`의 OFF 무시는 **문제 6 / K-32**, `is_data_repl_log_enabled`의 `default:return
  true`(DDL 항상 복제)는 **문제 9**, 혼합 ON/OFF 멀티테이블 SBR은 **K-52**, 소스측 OFF 참조는 **K2-1**,
  `is_data_repl_log_enabled` 링키지(static/헤더 없음)는 **K2-3**. `spec_has_replication_class`의 derived
  vclass 순회는 #6908 리뷰대로 올바르게 보강된 코드로 재확인.
- 파티션 승격 UNIQUE 플래그 오제거는 **문제 7 / K-14**, `has_notnull_unique_constraints`의 PK 미감지는

## 조사 종료 선언

3차 전수 재수색에서 위 A~G 전 영역을 diff 기준으로 다시 읽고, LSP 정의 점프·참조 추적으로 신규 함수
(`heap_get_class_repl_on`, `or_is_replication_candidate_key`, `btree_get_rkey_btid`,
`is_data_repl_log_enabled`, `spec_has_replication_class`, `check_ha_repl_constraint`,
`classobj_copy_pk_and_uk_notnull_constraints`, `us_hb_process_rkcheck` 등)의 호출자/피호출자를
확인했다. 이번 라운드에서 새로 정밀 검토한 후보 3건(① `btree_get_rkey_btid` NULL btid 미검사,
② `do_create_entity` OFF 분기 `break` vs `goto`, ③ `us_hb_process_rkcheck`의 sysprm 전역 변이)은
각각 **기존 성질(§5 기존)·동작상 등가·근거 부족**으로 판정되어 신규 결함으로 세지 않았다.

기존 67건 병합 목록과 내 유지 17건이 파서→카탈로그→서버 복제 판정→DDL/DML 경로→유틸리티에 이르는
이 기능 diff의 사실상 전 표면을 이미 덮고 있어, **잔여 쿼터(50−17=33)를 억지로 채우지 않고 유지 17건 +
신규 0건에서 조사를 종료**한다. 이 영역을 넘어서는 지적은 이 기능이 새로 만든 결함이 아니라 기존 코드의
성질이거나 스펙/문서 개정 사안이다.
