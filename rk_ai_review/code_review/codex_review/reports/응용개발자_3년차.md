- feature 근거/실행 경로: lexer 전용 token(`src/parser/csql_lexer.l:916-918`) → table option grammar(`src/parser/csql_grammar.y:19891-19996`); 일반 identifier 호환 production 추가 없음.
- develop 비교/PR: feature 신규; #6394/#7370.

- 수정·테스트: contextual keyword 처리; CCI/JDBC prepared SQL 포함 identifier 위치 회귀.

## APP3-08 — rename 기반 shadow swap은 replication constraint 재검사를 실행하지 않는다

- 심각도/신뢰도: **Medium / Medium**
- feature 근거/실행 경로: rename은 최종 entity name만 갱신한다(`src/query/execute_schema.c:1999-2008`). RK gate macro에는 `PT_RENAME_ENTITY`가 없고(`109-114`), 최종 검사도 `need_check_repl_constraint`일 때만 호출된다(`2059-2069`).
- develop 비교/PR: ON/OFF class semantics 도입으로 기존 rename이 신규 위험을 노출. #6477/#7370 범위.
- 재현/불변식: HA disabled 때 divergent OFF shadow table과 ON production table의 이름을 swap한 뒤 HA start/운영 이름 기준 배포를 수행. 논리 서비스 대상 변경 시 migration tooling이 기대하는 replication 상태가 검증돼야 한다.
- 수정·테스트: rename/swap 후 최종 대상의 RK/FK 상태를 검사하거나 명시적 ON/OFF 확인을 요구; 2-table rename 회귀.

- develop 비교/PR: replication FK 진단이 feature에 새로 추가되어 신규. #6505/#6658 및 #7370 inline review 맥락.

- 수정·테스트: NULL-safe PK lookup 및 구체적 catalog inconsistency 오류; schema migration 후 정상/OFF/missing-PK fixture 시험.
