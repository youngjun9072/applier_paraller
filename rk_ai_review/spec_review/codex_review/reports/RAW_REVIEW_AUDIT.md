# 확장 원시 리뷰 최종 감사 보고서

- 감사일: 2026-08-23
- 감사 대상: `reports/raw/*.md` 20개
- 기준 문서: `REVIEW_INSTRUCTIONS.md` 1~13절
- 실제 검사 규모: 초기 400개 + 추가 291개 = 총 691개
- 종합 판정: **통과** — 항목 수, ID, 필수 메타·소제목, 허용 값, 심각도, 종료 기록이 모두 기준을 충족한다. 보고서 간 동일 제목 1쌍은 형식 실패가 아니라 통합 대상으로 남는다.

## 1. 감사 범위와 판정 기준

다음 사항을 항목 경계 `## [역할-경력-번호] 제목`을 기준으로 검사했다.

1. 보고서 20개 존재 여부와 파일별 초기·추가·최종 항목 수
2. 1번부터 마지막 번호까지의 연속성, 파일 내부 ID 중복, 추가 번호 21~50 범위
3. 메타 필드 5종의 존재와 비어 있지 않은 값
4. 필수 소제목 5종의 존재와 비어 있지 않은 본문
5. 허용 심각도 `Blocker`, `Critical`, `Major`, `Minor`, `Suggestion`
6. 지나치게 짧은 본문과 예제의 실질성에 대한 길이 기반 후보 선별
7. 정확히 같은 제목, 기호·공백을 제거한 정규화 제목, 본문 전체가 동일한 항목
8. 추가 조사 종료 기록, 선언한 추가·최종 수와 실제 수의 일치, 종료 사유와 미확인 영역

길이 검사는 형식 오류를 찾기 위한 휴리스틱이다. 각 필수 소제목 본문을 Markdown 기호를 제외하고 40자 미만이면 검토 대상으로, 예제 본문은 80자 미만이면 추가 수동 확인 대상으로 삼았다. 짧다는 사실만으로 내용 결함이라고 단정하지 않았다.

## 2. 자동 검사 명령

전체 필드와 소제목 개수는 다음 명령으로 재현할 수 있다.

```bash
for pat in '^- 분류:' '^- 심각도:' '^- 근거 위치:' \
  '^- 사실/추론 구분:' '^- 영향 대상:' '^### 문제$' \
  '^### 왜 중요한가$' '^### 재현 또는 구체적 예제$' \
  '^### 권고안$' '^### 검증 방법$' '^# 추가 조사 종료 기록$'
do
  printf '%s ' "$pat"
  rg -c "$pat" codex_review/reports/raw/*.md |
    awk -F: '{sum += $2} END {print sum}'
done
```

항목 경계별 상세 검사는 다음 Python 표준 라이브러리 스크립트로 수행했다. 이 명령은 파일을 읽기만 하며 원시 보고서를 수정하지 않는다.

```bash
python3 - <<'PY'
from pathlib import Path
import collections, re

allowed_severity = {'Blocker', 'Critical', 'Major', 'Minor', 'Suggestion'}
metadata = ['분류', '심각도', '근거 위치', '사실/추론 구분', '영향 대상']
sections = ['문제', '왜 중요한가', '재현 또는 구체적 예제', '권고안', '검증 방법']
total = added = 0

for path in sorted(Path('codex_review/reports/raw').glob('*.md')):
    text = path.read_text()
    heads = list(re.finditer(r'^## \[([^\]]+)-(\d+)\]\s+(.+?)\s*$', text, re.M))
    numbers = [int(m.group(2)) for m in heads]
    total += len(heads)
    added += sum(n >= 21 for n in numbers)
    assert len(numbers) == len(set(numbers))
    assert numbers == list(range(1, max(numbers) + 1))
    assert max(numbers) <= 50

    for index, head in enumerate(heads):
        end = heads[index + 1].start() if index + 1 < len(heads) else len(text)
        body = text[head.end():end].split('\n# 추가 조사 종료 기록', 1)[0]
        for field in metadata:
            assert re.search(r'^- ' + re.escape(field) + r':\s*\S', body, re.M)
        for section in sections:
            assert re.search(r'^### ' + re.escape(section) + r'\s*$', body, re.M)
        severity = re.search(r'^- 심각도:\s*(\S+)', body, re.M).group(1)
        assert severity in allowed_severity

    assert re.search(r'^# 추가 조사 종료 기록\s*$', text, re.M)

print(total, added)
PY
```

위 스크립트의 핵심 출력은 `691 291`이며 assertion 실패는 없었다. 별도 제목·길이 검사에서는 필수 소제목 본문 40자 미만 0건, 예제 본문 최소 길이 77자, 정확히 같은 본문 0건이 나왔다.

## 5. 빈 내용·짧은 내용·예제 실질성

- 비어 있는 필수 메타: 0건
- 누락된 필수 소제목: 0건
- 필수 소제목 본문 40자 미만: 0건
- 예제 본문 최소 길이: 77자
- 예제 본문 80자 미만 후보: 2건
- fenced code block이 없는 예제: 196건

80자 미만 후보는 `USER-10Y-28`과 `USER-1Y-21`이다. 두 항목을 직접 확인한 결과 각각 네트워크 분할 뒤 상충하는 RK/복제 정책 상태, 일반 계정의 `ALTER TABLE ... REPLICATION=OFF` 권한 오류를 구체적으로 제시하고 기대 결과의 누락까지 설명한다. 따라서 빈 예제나 수량 채우기용 문장으로 판정하지 않았다.

196개 예제에 fenced code block이 없지만 지시서 6·7절은 SQL뿐 아니라 이벤트 순서와 엔진·운영 상태 예제도 허용한다. 코드 블록 부재 자체는 결함이 아니다. 자동 길이 검사는 691개 모두를 통과했으나, SQL의 실제 CUBRID 문법 지원 여부와 각 예상 동작의 기술적 타당성은 이 형식 감사만으로 보증할 수 없다.

## 7. 추가 조사 종료 사유 검사

20개 파일 모두 다음을 충족했다.

- 종료 기록이 정확히 1개 존재한다.
- 실제 추가 항목 수와 선언 수가 일치한다.
- 최종 항목 수와 선언 수가 일치한다.
- `추가 조사에서 확인하지 못한 영역`이 비어 있지 않다.
- 30개 미만 종료 사유가 기록돼 있다.

종료 사유는 20개 모두 지시서 예시와 같은 “가치 있는 독립 쟁점을 더 찾지 못했으며, 기존 항목의 반복이나 근거 없는 추측으로 수량을 채우지 않음”이다. 형식상 유효하고 무리하게 50개를 채우지 않았다는 원칙에도 맞는다. 다만 모든 파일이 같은 일반 문구만 사용하므로, 각 관점에서 어떤 검색·비교를 마친 뒤 중단했는지까지 입증하지는 않는다. 그 근거는 각 파일의 `추가 조사에서 확인하지 못한 영역`과 실제 추가 항목 내용으로 보완해서 판단해야 한다.

## 8. 최종 결론과 후속 조치

총 691개 원시 항목은 수량·연속 번호·필수 구조·허용 메타 값·심각도·종료 기록 기준을 충족한다. 빈 항목, 40자 미만 필수 본문, 중복 ID, 동일 본문은 발견되지 않았다. `PM-10Y-08`의 이전 형식 결함 2건도 수정 후 재검사를 통과했다.

이번 감사에서는 내용상 판단이 필요한 원시 항목을 수정하지 않았다. 따라서 원시 보고서 20개는 감사 전 상태 그대로다.
